# Evidence-gated roadmap and possible venues

No delivery dates, assigned partners or likelihood of adoption are promised.
Owners remain unassigned until volunteers accept an issue. Negative findings can
stop or redirect work. Record decisions, alternatives and dissent publicly.

| Gate | Exit evidence | Current position |
|---|---|---|
| G0 problem/provenance | origin, rights inventory, prior-art comparison | repository origin recorded; wider IP/prior art incomplete |
| G1 syntax | independent parsers and shared positive/negative vectors | reference tests exist; second implementation pending |
| G2 trust/privacy | independent review and replay/binding/downgrade experiments | proposed architecture; authenticity/binding unvalidated |
| G3 interoperability | supported simulator then independent device trials | NOT_MEASURED here |
| G4 enforcement | consented tracing into actual capture/storage/upload | NOT_MEASURED here |
| G5 venue/publication | fit, stakeholder/IP review, explicit authorization | no submission/release authorized |

Possible paths assessed using primary process sources on 2026-10-21:

- **IETF:** consider a scoped Internet protocol/interoperability problem. An
  individual Internet-Draft can start discussion; group adoption and publication
  review are separate. Neither a draft nor every RFC is an Internet Standard.
  Review current group scope and BCP 78/79 obligations before any submission.
  [IETF process](https://www.ietf.org/process/process/).
- **ISO/IEC:** assess relevant technical scope, including joint IT work where
  relevant, and national-body/expert routes. Proposals require expert work,
  consensus and approval under the applicable process. No committee fit or
  nomination is established. [ISO process](https://www.iso.org/developing-standards.html).
- **W3C:** assess only where web semantics/APIs fit. Community exploration and
  Recommendation-track work are distinct; a community report is not a W3C
  Recommendation. Inspect group terms and patent obligations before joining.
  [Groups/policies](https://www.w3.org/community/about/),
  [web standards](https://www.w3.org/standards/).

These are alternatives to investigate, not a required three-body sequence.
Prefer compatible existing work when a new standard's gap cannot be justified.
