# Discussion, review and publication

[Discussions](https://github.com/Thom-Code-Cell/personal-privacy-signal/discussions)
is enabled, checked 2026-10-21. Use existing categories for questions, ideas and
voluntary replication. Issues hold bounded work/results; PRs hold patches and
review. Link decisions across channels. Use [private reporting](../SECURITY.md)
for vulnerabilities. Draft-branch templates/policies may not populate GitHub's
default-branch interface until merge. No automated announcement is configured.

## Archive and DOI gates

1. Select reviewed commit/scope. Verify rights/notices, author roles and consent,
   privacy, independent review, final-head checks and remaining limitations.
2. Prepare changelog, commit, reproducible artifacts/checksums and measured versus
   unmeasured claims. Keep protocol/package/repository versions distinct.
3. Obtain explicit release/archive approval. Check deposit terms and metadata;
   passing CI or this plan is not approval.
4. If authorized, consider [Zenodo GitHub archiving](https://help.zenodo.org/docs/github/)
   or manual deposit. Review automatic release-archiving behaviour before linking
   accounts. No integration, release or deposit was activated here.
5. Only after a real deposit, verify DOI resolution/version metadata and update
   CITATION.cff with actual identifier/date. Never fabricate a DOI or published
   version. Cite version DOI for reproduction; distinguish concept DOI if used.
